## 三、核心验收：群聊触发一次反思

### 3.1 触发条件（重要）

反思需要**攒够 6 轮**或**空闲 10 分钟**，满足其一即触发：

- 想快：在群里连续聊 6 轮以上（每轮 = 一次机器人回复）
- 想慢：聊 1~2 轮后停手，等 10~20 分钟

注意 `tick` 扫描间隔也是 600 秒，所以空闲触发实际落在 **10~20 分钟**。

如果群里没攒够 6 轮又不想等，可以临时在 WebUI 改阈值——但 schema 里没暴露这三项，需改配置文件（见附录）。

### 3.2 必须 @ 机器人

群里要让天使之心接管上下文，需要点名：

- **@机器人说话**（最稳）
- 或引用机器人消息
- 或正文含人格名/别名

离场状态下普通消息会被跳过（`enter_on_mention_only` 默认 true）。

### 3.3 抓日志

```bash
docker logs astrbot 2>&1 | grep -E "上下文已注入|反思调度|反思执行" | tail -40
```

## 四、按顺序核对的四个点

### 核对点 1：新字段生效

```
AngelHeart[...]: 上下文已注入 event.angelheart_context records=N historical=H batch=B
```

**期望**：出现 `historical=` 和 `batch=` 两个新计数，且 `historical + batch == records`。

**失败含义**：heart 没更新到这个分支。

> 私聊不会走这条路径（`takeover_private_chat_context` 默认 false），测试必须用群聊。

### 核对点 2：切分走显式分支

```
[反思调度] 使用天使之心聊天记录: 来源=explicit batch=N/total=M
```

**期望**：`来源=explicit`。

| 实际值 | 含义 |
| --- | --- |
| `explicit` | ✅ 按声明切分，目标状态 |
| `legacy_flag` | 快照里还有 `is_processed`，heart 版本不对 |
| `role_fallback` | 拿不到 `historical_count`，heart 没更新 |
| `role_fallback_full` | 切空兜底，可接受但需观察 |

### 核对点 3：反思入池

```
[反思调度] 入缓冲 session=... pending_turns=N records=M
```

**期望**：`records > 0`，且 `pending_turns` 逐轮递增。

**这是本次修复的核心验证点**。修复前这里恒为 `本轮无消息入池`。

### 核对点 4：反思真正产出记忆

```
[反思调度] 触发 reason=count session=... turns=6 records=M
[反思执行] 开始 session=...
[反思执行] 完成 session=... useful=N new=M
```

**期望**：`new > 0`（或至少 `useful > 0`）。

**注意**：`new=0` 不一定失败——小模型可能判断这段对话不值得记。若连续多轮都 `new=0`，才算异常。

## 六、召回是否恢复

群里再发一句话，观察：

```
[astrbot_plugin_angel_memory] [INFO] [services.retrieval_service:67]: 🧠 灵魂回忆深度: 7 (E=...)
[astrbot_plugin_angel_memory] [DBUG] [service.memory_manager:380]: 链式回忆: 实体记忆=X, 类型记忆=Y, 总计=Z
```

**期望**：`总计 > 0`（有记忆后）。

`E=` 后面的能量值也应开始不为 0（灵魂共鸣恢复）。

## 七、需要留意的异常

| 现象 | 可能原因 |
| --- | --- |
| `historical + batch != records` | heart 侧切分计算错误，请把日志发我 |
| `来源=role_fallback_full` 频繁出现 | 批次反复切空，兜底在兜整块，需检查压缩行为 |
| `入缓冲` 有值但永不 `触发` | 阈值未达成，或 tick 未运行，检查 `[反思调度] 开始 tick=` |
| `pending_turns` 不递增 | 每轮都被判为重复（时间戳+内容去重命中） |
| 反思 `new` 恒为 0 | 小模型判定不记；或 scope/画像过滤问题 |
| 出现 `检测到异常消息，该消息不存在用户和ID` | 快照里有占位身份，属既有过滤逻辑，记录数量即可 |

## 八、快速判定表

| 核对点 | 通过标准 |
| --- | --- |
| 1. 版本 | 2.2.9 / 1.6.16 |
| 2. 注入日志 | 含 `records/historical/batch` |
| 3. 切分来源 | `explicit` |
| 4. 入缓冲 | `records > 0`，`pending_turns` 递增 |

## 附录：调整触发阈值

三项阈值未在 WebUI 暴露，需改配置文件：

```bash
docker exec astrbot bash -lc 'grep -n "reflection" /AstrBot/data/config/astrbot_plugin_angel_memory_config.json'
```

若不存在，可手工加入（键名在 `memory_behavior` 下）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `reflection_turn_threshold` | 6 | 攒够多少轮触发 |
| `reflection_idle_seconds` | 600 | 空闲多少秒触发 |
| `reflection_tick_seconds` | 600 | 后台扫描间隔 |

改后需重载插件。**验收阶段建议先保持默认**，确认修复生效后再按需调整。
