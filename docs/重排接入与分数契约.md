# 重排接入与分数契约

## 上游契约

插件不直连重排服务，通过 `context.get_rerank_provider_by_id()` 拿到 AstrBot 的
`RerankProvider` 实例后调用 `rerank()`。

- 返回类型是 `list[RerankResult]`（`astrbot/core/provider/entities.py`）。
- 字段只有 `index: int` 和 `relevance_score: float`，**没有 `score`**。
- 各 source（vllm / tei / bailian / xinference / nvidia）只做 JSON → 对象的转换，
  不保证排序顺序；顺序不可作为分数使用。

## 插件侧解析

所有重排返回都必须经过 `llm_memory/utils/rerank_utils.py::extract_rerank_items()`：

- 同时兼容 `RerankResult` 对象与原始 JSON dict；
- 分数优先取 `relevance_score`，缺失时回退 `score`；
- 两者都缺失时保留 `None`，由调用方决定降级，不伪造 0。

消费方：

| 位置 | 用途 |
|---|---|
| `llm_memory/components/hybrid_retrieval_engine.py` | 记忆候选重排，按 max 归一化 |
| `llm_memory/components/note_chunk_search.py` | 笔记切片重排 |
| `web_api/debug_api.py` | WebUI 重排探针展示 |

## 踩坑记录

曾按 `getattr(item, "score")` 读取对象，导致所有分数变成 `None`：

- 探针显示全 0（上游 issue #83）；
- 记忆链路 `max_score = 0`，退化为按返回顺序发 rank 分数，伪造的 1.0/0.98
  让下游 0.5 阈值大量放行；
- 笔记链路直接丢弃对象结果，降级回 BM25。

新增重排消费方时不要自己写字段提取，直接复用 `extract_rerank_items()`。
