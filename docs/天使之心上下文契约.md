# 天使之心上下文契约（angelheart_context）

## 谁产出、谁消费

| 角色 | 说明 |
| --- | --- |
| 产出方 | `astrbot_plugin_angel_heart`，在 `roles/front_desk.py` 的 `_process_decision_result` 中注入 |
| 消费方 | 任意下游插件；本项目内为 `astrbot_plugin_angel_memory` |
| 注入时机 | 秘书判定「要回复」之后、主模型请求之前 |

注入点日志：

```
AngelHeart[chat]: 上下文已注入 event.angelheart_context records=N historical=H batch=B
```

`batch = B` 即本字段声明的当前连续块长度，排障时先看这一行。

## 字段

```json
{
  "chat_records": [ ... ],
  "historical_count": 1,
  "secretary_decision": { ... }
}
```

### `chat_records`

当前会话的**全量快照**，不是增量。结构为：

```
historical_context + recent_dialogue
└─ 前 historical_count 条 ─┘ └─ 其余为当前连续块 ─┘
```

单条记录常见字段：

| 字段 | 说明 |
| --- | --- |
| `role` | `user` / `assistant` / `tool` / `system` |
| `content` | 字符串，或 `[{"type": "text", "text": "..."}]` 形式的多模态列表 |
| `sender_id` / `sender_name` | 发送者身份；`assistant` 为机器人自身 |
| `sender_role` | 群主/管理/群友，可能为空串 |
| `source_message_id` | 平台消息 ID，可用于精确定位 |
| `timestamp` | Unix 秒 |
| `kind` | 摘要块为 `context_summary`，普通消息无此字段 |

### `historical_count`

**语义：`chat_records` 前 N 条属于历史前缀（摘要/已压缩内容），其后为当前连续块。**

- 恒存在，纯当前块时为 `0`
- 生产方按自己的压缩策略计算，消费方不得猜测 `role` 结构来推断边界
- 越界值会原样输出，由消费方判定非法并退回兜底，不在此处静默改写

### `secretary_decision`

秘书的判定结果，字段随决策模型变化，消费方只应读取自己需要的键。

## 消费方义务

1. **优先读 `historical_count`** 切分当前块，不要用 `role == "assistant"` 反推边界。
2. **不要依赖 `is_processed`**。该字段已于 `317c520`（2026-07-13，v2.0.0）退役，快照中不再出现。
3. **本轮用户消息与助理回复不从快照取**。快照生成于主模型回复之前，末尾是本轮用户消息，不含本轮回复；两者应分别取自 `event` 与 `response`。

## 已退役字段

| 字段 | 退役版本 | 替代 |
| --- | --- | --- |
| `is_processed` | v2.0.0（`317c520`） | `historical_count` + 消费方自行使用 `event` / `response` |

退役原因：该字段把「哪些是本轮新增」的语义寄托在账本内部状态上，压缩策略一变即失效，且消费方无从感知。

## 兼容矩阵

| angel_heart | angel_memory | 结果 |
| --- | --- | --- |
| ≥ 2.2.9 | ≥ 1.6.16 | 按 `historical_count` 精确切分 |
| < 2.2.9 | ≥ 1.6.16 | 无该字段，消费方退回 `role` 兜底或旧标记逻辑 |
| ≥ 2.2.9 | < 1.6.16 | 新字段被忽略，旧消费方行为不变（仍可能为空） |

三个方向均不抛异常，允许两侧独立升级。
