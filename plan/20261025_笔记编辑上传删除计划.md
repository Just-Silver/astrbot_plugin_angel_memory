# 笔记编辑 / 上传 / 删除计划（2026-10-25）

## 0. 一句话

给天使之魂的笔记补上三件事：**AI 能改（不能删）**、**人类能在 WebUI 删（单条 + 批量，二次确认）**、**人类能在 WebUI 传**，并且文件、索引、切片、检索四处始终一致。

---

## 1. 目标与边界

### 1.1 要做的

| # | 能力 | 使用方 | 说明 |
|---|---|---|---|
| 1 | 编辑笔记局部内容 | Agent | 照搬 opencode `edit`：`old_string` → `new_string` |
| 2 | 整篇覆盖笔记 | Agent | 照搬 opencode `write`：`content` 全文替换 |
| 3 | 单条删除 | 人类（WebUI） | 索引页每行一个删除按钮 |
| 4 | 批量删除 | 人类（WebUI） | 勾选多行后一次删除 |
| 5 | 二次确认 | 人类（WebUI） | 单条、批量都弹确认框，列出将被删除的文件 |
| 6 | 正文预览 | 人类（WebUI） | 索引页点开直接看正文，替代现在的 JSON 详情 |
| 7 | 上传笔记 | 人类（WebUI） | 默认取正文 H1 当标题，提交前可改，落盘到 `raw/upload/` |

### 1.2 明确不做

- **不给 Agent 删除能力**（任何形式，包括「删除某一段」）。
- **不做 `.bak` 自动备份**（用户已明确不需要）。
- **不向量化笔记**（保持现有 BM25 + 可选 rerank 架构）。
- **不做多文件原子补丁**（opencode 的 `patch` 工具对单文件笔记没有收益）。
- **不改文件名**：重命名会改变 `file_id`，等于换一篇笔记，Short ID 会变。编辑只动正文。
- **不动 `.txt` / `.md` 之外的格式**。
- **不动索引粒度与检索性能**：切片大小（220 字符）、`max_chunks_per_file`、Tantivy schema、`updated_at` 索引均保持现状。规模问题另议。

## 2. 现状

### 2.1 四层存储（改动的对象）

```text
data/plugin_data/astrbot_plugin_angel_memory/
├─ raw/                                      ← 正文，纯文本，唯一真相源
│   ├─ .angel/note/*.md                      ← AI 写的
│   └─ upload/*.md                           ← 本计划新增（人类上传）
└─ memory_center/index/
    ├─ simple_memory.db → note_index_records  ← 元数据（无正文列）
    ├─ note_chunks.db   → chunks              ← 切片正文 + 行号区间
    └─ tantivy_note_chunks/                   ← BM25 倒排索引
```

`note_index_records` 主键是 `source_id = "note_file_{file_id}"`，`file_id` 由**相对路径**生成。所以：

```text
同路径 → 同 file_id → 同 note_short_id   （编辑安全）
换路径 → 新 file_id → 新 note_short_id   （重命名等于换一篇）
```

### 2.2 现有工具与接口

| 类型 | 名称 | 现状 |
|---|---|---|
| LLM 工具 | `angel_note_create` | 只新建，文件名带时间戳，永不覆盖 |
| LLM 工具 | `angel_note_read` | 分页读，返回带元信息头（`[angel_note_read]` + 4 行字段） |
| HTTP | `GET  /notes` | 分页/关键词浏览 |
| HTTP | `POST /notes/recall` | 按 `note_short_id` 读正文 |
| HTTP | `GET  /notes/files` | 列出 raw/ 下全部 `.md`/`.txt` |
| HTTP | `GET  /notes/file-content` | 按路径读文件 |
| HTTP | 无 | **没有删除、没有上传** |

### 2.3 本计划顺带修的缺陷

1. `POST /notes/recall` 参数为空时 `int(None)` 抛异常 → 返回 500。改为返回 400 + 中文提示。
2. `note_service.remove_file_data()` 用 `Path(file_path).name` 反查 `file_id`，不同目录同名文件会串。新代码**一律用库里的 `file_id`**，不走这条路径。

## 3. Agent 编辑（照搬 opencode）

参考实现：`opencode/packages/core/src/tool/plugin/edit.ts` 与 `write.ts`。

### 3.1 工具组

```text
angel_note_create   新建（已有，不动）
angel_note_read     读（已有，不动）
angel_note_edit     局部替换（新增，对标 opencode edit）
angel_note_write    整篇覆盖（新增，对标 opencode write）
```

### 3.2 `angel_note_edit` 规格

**参数**

```json
{
  "note_short_id": { "type": "integer", "minimum": 0, "description": "笔记短ID" },
  "old_string":    { "type": "string", "description": "要被替换的原文（必须与笔记正文逐字一致，不含 angel_note_read 的元信息头）" },
  "new_string":    { "type": "string", "description": "替换后的文本（必须与 old_string 不同）" },
  "replace_all":   { "type": "boolean", "default": false, "description": "是否替换所有出现位置。默认 false 时 old_string 必须只出现一次" }
}
```

**执行顺序**（任一检查失败即返回错误，不写盘）

| # | 检查 | 返回 |
|---|---|---|
| 1 | `old_string == new_string` | `没有变化：old_string 与 new_string 相同。` |
| 2 | `old_string == ""` | `old_string 不能为空。新建笔记请用 angel_note_create，整篇覆盖请用 angel_note_write。` |
| 3 | 按 `note_short_id` 查不到记录 | `未找到 note_short_id={id} 对应的笔记。` |
| 4 | 拼出的绝对路径不在 `raw/` 内 | `路径越界。` |
| 5 | 文件不存在 | `文件不存在：{相对路径}` |
| 6 | 匹配 0 处 | `在笔记中找不到 old_string。它必须与原文完全一致，包括缩进和空行。` |
| 7 | 匹配 >1 处且 `replace_all=false` | `找到 {n} 处匹配，但默认只允许一处。请补充更多上下文使其唯一，或设 replace_all=true。` |
| 8 | 替换后与原文相同 | `没有变化：这次编辑没有改动文件。` |
| 9 | 读盘后 mtime 变了（见 6.3） | `文件已被其他写入改动，请重新读取后再编辑。` |

**成功返回**

```text
[angel_note_edit]
note_short_id: 3
source_file_path: .angel/note/登录方案_20261025.md
replacements: 1
title: 登录方案（2026-10-25 修订）        ← 仅当 H1 被改时出现
已更新正文并重建索引（切片 {n} 段）。
```

### 3.3 `angel_note_write` 规格

**参数**

```json
{
  "note_short_id": { "type": "integer", "minimum": 0, "description": "笔记短ID" },
  "content":       { "type": "string", "description": "完整的新正文（会替换文件全部内容）" }
}
```

**检查**

| # | 检查 | 返回 |
|---|---|---|
| 1 | `content.strip() == ""` | `content 不能为空。` |
| 2 | 记录不存在 | `未找到 note_short_id={id} 对应的笔记。` |
| 3 | 路径越界 | `路径越界。` |
| 4 | 文件不存在 | `文件不存在：{相对路径}` |
| 5 | 内容与原文相同 | `没有变化：新内容与当前正文一致。` |
| 6 | mtime 冲突 | 同 edit |

**成功返回**：`已覆盖正文（{n} 行），并重建索引（切片 {m} 段）。`

### 3.4 匹配算法（三级降级）

完全对标 opencode `matchView`：

```text
第 1 级：精确匹配（字节级）
第 2 级：归一化后匹配
         ' ' ' ‚ ‛  → '      “ ” „ ‟  → "
         ‐ ‑ ‒ – — ― − → -
         全角/窄空格（U+00A0, U+2002-200A, U+202F, U+205F, U+3000）→ 普通空格
第 3 级：按行匹配，每行比较前 trimEnd()，并忽略上述字符差异
```

三级都 0 命中才报「找不到」。第 3 级命中时，替换区间取**整行范围**（含行尾换行，与 opencode 一致）。

### 3.5 行尾处理

- 匹配在 **LF 视图**上做（把 `\r\n` 折叠成 `\n` 后再找），因为 `angel_note_read` 返回给模型的内容就是 LF。
- 写回时判断原文件：
  - 全文都是 `\r\n` → 写回 `\r\n`
  - 其他情况（纯 LF 或混合）→ 写回 `\n`
- 不做「逐行还原混合行尾」的复杂处理：笔记不是代码，统一行尾的收益大于风险。

### 3.6 工具提示词（定稿）

`angel_note_edit`：

```text
编辑已有笔记：把 old_string 精确替换为 new_string，两者必须不同。
默认 old_string 必须只出现一次；出现多次时补充更多上下文使其唯一，或设 replace_all=true 替换全部。
old_string 必须与笔记原文逐字一致（含缩进、空行、行尾换行），
且不要包含 angel_note_read 返回的元信息头（note_short_id / source_file_path / total_lines 那几行）。
匹配失败时会依次忽略弯引号、破折号、全角空格，再忽略每行行尾空白的差异重试；仍失败则报错且不写盘。
你看到的笔记内容通常只是切片，不是全文。编辑前请先调用 angel_note_read 读取完整正文，再从正文中摘取 old_string。
笔记标题是正文第一行以 "# " 开头的行，改标题就替换那一行。
本工具不能新建笔记（用 angel_note_create），也不能整篇覆盖（用 angel_note_write）。
```

`angel_note_write`：

```text
整篇覆盖已有笔记的正文，用于大范围重写；局部修改请用 angel_note_edit。
content 是完整的新正文，会替换文件全部内容，不可撤销。
不会新建笔记（用 angel_note_create）。建议先 angel_note_read 确认当前内容再覆盖。
```

### 3.7 与 opencode 的差异及原因

| opencode | 本计划 | 原因 |
|---|---|---|
| `path` 参数 | `note_short_id` | 模型只从检索结果拿到短 ID；短 ID 天然防越界 |
| 提示词提「不要带 Read 的行号前缀」 | 改为「不要带 angel_note_read 的元信息头」 | 我们的 read 不带行号，但带头部字段 |
| 权限审批 `permission.assert` | 无 | AstrBot 插件工具没有审批机制；靠唯一性约束兜底 |
| `Formatter.file()` 格式化 | 无 | 笔记不跑格式化器 |
| `Bom.split/join` 保 BOM | 读时用 `utf-8-sig`，写时保持无 BOM | 简化，避免 BOM 泄漏进正文 |
| 文件锁 `withLock` | 原子写 + mtime 乐观锁（见 6.2 / 6.3） | 跨进程安全，且能防文件监控读到半截 |

## 4. WebUI 删除（人类）

### 4.1 交互

索引页（`NoteIndexView.vue`）：

```text
┌ 关键词搜索 ────────────────────── [🔍] ─┐
│ [⬆ 上传笔记]  [🗑 删除选中 (2)]          │   ← 未勾选时批量按钮禁用
├──┬────────┬──────────────┬────────┬────┬──────┤
│☑ │Short ID│ 文件路径      │ 标题   │行数│ 操作 │
│☑ │   3    │ .angel/note/… │ 登录方案│ 86 │👁 🗑│
│☐ │   2    │ upload/接口…  │ 接口文档│ 42 │👁 🗑│
└──┴────────┴──────────────┴────────┴────┴──────┘
```

- 表格启用 naive-ui 原生 `type: 'selection'` 列；
- 「操作」列 = `👁` 预览 + `🗑` 删除；
- 预览弹窗：标题、相对路径、总行数、正文（`<pre>` 滚动），底部「删除」按钮；
- 删除确认弹窗（单条与批量共用）：警告色，列出**全部**将删除的相对路径；单条额外显示行数与更新时间。

### 4.2 接口

```text
POST /astrbot_plugin_angel_memory/notes/delete
Body: { "source_ids": ["note_file_12", "note_file_15"] }
200 : { "deleted": ["note_file_12"], "failed": [{"source_id": "note_file_15", "reason": "文件不存在"}] }
400 : 参数为空
```

- 单条删除也走这个接口，前端传 1 个元素的数组（后端只有一条路径）。
- 用 `source_id`（表主键）而不是 `note_short_id`：后者可能为 `-1`（历史迁移残留），做主键不安全。

### 4.3 删除顺序与补偿

```text
对每个 source_id：
  1. 查 note_index_records → 拿 file_id + source_file_path
  2. 路径校验：解析后必须在 raw/ 内，否则 failed("路径越界")
  3. 删文件（缺失则视为已删，继续）
  4. note_service.remove_file_data_by_file_id(file_id)
       → 清 note_index_records 行
       → 清 note_chunks.db 切片
       → 清 Tantivy 文档
  5. 记入 deleted；任一步抛异常 → 记入 failed，不影响其他条目
```

**顺序理由**：先删文件再清索引。若反过来，中途失败会留下「索引没了但文件还在」的孤儿文件——文件监控之后会把它重新收编，白删一场。先删文件则最坏情况是「文件没了、索引残留」，文件监控下一轮会兜底清掉。

**幂等**：文件监控发现文件消失时也会清同一批数据，重复清理无害（按 `file_id` 删，删不到就是 0 行）。

## 5. WebUI 上传（人类）

### 5.1 交互

```text
[⬆ 上传笔记] → 选文件（可多选，.md/.txt）
   → 逐个解析 → 弹窗：

   ┌ 上传笔记 ──────────────────────────────┐
   │ 原文件：接口文档.md                      │
   │ 标题：  [ 接口文档            ]  ← 可改  │
   │ 将保存为：raw/upload/接口文档.md         │
   ├────────────────────────────────────────┤
   │ # 接口文档                              │
   │ ## 鉴权                                │
   │ 所有接口走 Bearer Token…      ← 正文预览 │
   ├────────────────────────────────────────┤
   │                    [取消]  [确认上传]    │
   └────────────────────────────────────────┘
```

- 标题默认取正文第一个 `# ` 行；
- 正文没有 H1 时，默认取文件名（去扩展名），并在弹窗里提示「正文无标题，已使用文件名」；
- 用户改了标题 → 落盘时同步改写正文 H1（有则替换第一处 `# ` 行，无则文件头插入 `# {标题}\n\n`）；
- 用户没改标题 → **正文一个字节都不动**；
- 「将保存为」实时随标题变化，用户知道自己会得到什么文件名。

### 5.2 接口

上传走 **JSON + base64**，不使用 multipart：前端 `FileReader.readAsDataURL()` 拿到 base64，后端负责解码与编码探测。这样不依赖 AstrBot 插件页 bridge 的 `upload()` 字段名约定。

```text
POST /astrbot_plugin_angel_memory/notes/upload
Body: { "filename": "接口文档.md", "base64": "IyDmjqXlj6PmlofmoaM..." }
200 : {
        "preview": {
          "filename": "接口文档.md",
          "extension": ".md",
          "size_bytes": 1234,
          "encoding": "utf-8",
          "title": "接口文档",
          "title_source": "h1",          // 或 "filename"
          "content": "…完整正文…"
        }
      }
```

```text
POST /astrbot_plugin_angel_memory/notes/upload/confirm
Body: { "filename": "接口文档.md", "title": "接口文档（含鉴权）", "content": "…" }
200 : { "saved": { "relative_path": "upload/接口文档（含鉴权）.md",
                   "note_short_id": 7, "title": "接口文档（含鉴权）" } }
```

两步分开的理由：预览不落盘，用户取消就什么都没发生。

### 5.3 文件名规则

```text
目录     : raw/upload/
文件名   : sanitize(title) + 原扩展名
sanitize : 去掉 \ / : * ? " < > | 与控制字符，压缩空白，截断到 80 字符
冲突     : upload/接口文档.md 已存在 → upload/接口文档_20261025_153000.md
```

**绝不覆盖同名文件。**

### 5.4 校验

| 项 | 规则 | 失败返回 |
|---|---|---|
| 扩展名 | `.md` / `.txt` | `只支持 .md 和 .txt 文件。` |
| 大小 | ≤ 2 MB | `文件超过 2 MB 上限。` |
| 编码 | 依次尝试 `utf-8-sig` → `gbk` | `无法识别文件编码，请另存为 UTF-8。` |
| 内容 | 去空白后非空 | `文件内容为空。` |

## 6. 同步与并发

### 6.1 统一写入口

所有「改了文件内容」的路径，都必须在写完之后调用同一个函数：

```python
await asyncio.to_thread(note_service.parse_and_store_file_sync, str(abs_path), relative_path)
```

它负责一次做完：`file_id` 复用（同路径天然复用）→ 更新 `note_index_records`（标题、行数、mtime）→ 重建该文件的切片 → 更新 Tantivy。

涉及路径：`angel_note_edit`、`angel_note_write`、上传确认。删除路径见 4.3。

### 6.2 原子写

不做「打开文件写一半」：

```text
1. 写 <目标同名>.tmp.<随机后缀>
2. os.replace(tmp, 目标)      ← 同分区原子替换
3. 失败则删 tmp 并抛出
```

好处：文件监控任何时刻读到的都是**完整的旧版本或完整的新版本**，不会读到半截。

### 6.3 乐观锁（防丢更新）

```text
读文件时记下 mtime
  → 改完准备写回前，再 stat 一次
  → mtime 变了 → 放弃写入，返回「文件已被其他写入改动，请重新读取后再编辑」
```

覆盖 Agent 编辑与人类上传确认两处。这挡住的是：模型读完到写回之间，人类在 WebUI 或 NAS 上改了同一个文件。

### 6.4 与文件监控的关系

- 我们写完立刻建索引，文件监控之后扫到同样的 mtime，`_compare_file_states` 判定无变化，不会重复处理；
- 我们删完立刻清索引，监控扫到文件消失，再清一次（幂等）；
- 进程内并发（多个工具同时改同一文件）：由 6.2 的原子写 + 6.3 的 mtime 检查共同兜底，不额外引入全局锁。

## 8. 测试计划

在容器内执行（宿主机无 docker 时用本地 venv 替代）：

```bash
python -m pytest -q
```

### 8.1 匹配算法（纯函数）

| 用例 | 期望 |
|---|---|
| 精确命中一处 | 返回 1 个区间 |
| 同一段出现两次、`replace_all=false` | 报「多处匹配」 |
| 同一段出现两次、`replace_all=true` | 两处都被替换 |
| 弯引号 vs 直引号 | 能被第 2 级匹配到 |
| 行尾多一个空格 | 能被第 3 级匹配到 |
| 完全不存在的文本 | 报「找不到」 |
| 替换后内容不变 | 报「没有变化」 |

### 8.2 编辑落盘与同步

| 用例 | 期望 |
|---|---|
| 改正文一段 | 文件内容变；`note_index_records` 行数更新；切片重建；`note_short_id` 不变 |
| 改第一行 `# 标题` | 索引里的标题跟着变 |
| 目标文件在 `raw/` 之外 | 拒绝，文件不动 |
| 写完前后 mtime 被外部改动 | 拒绝，文件保持外部那版 |

### 8.3 删除

| 用例 | 期望 |
|---|---|
| 删 1 篇 | 文件消失；`note_index_records` 无此行；该 `file_id` 的切片与 Tantivy 文档消失 |
| 批量删 2 篇（共 3 篇） | 只删指定 2 篇，第 3 篇内容与索引都还在 |
| 删不存在的 `source_id` | 计入 `failed`，不影响同批其他条目 |
| `source_ids` 为空 | 400 |
| 路径越界的记录 | 拒绝删除，文件不动 |

### 8.4 上传

| 用例 | 期望 |
|---|---|
| 正文有 `# 标题` | 预览标题 = H1，`title_source = "h1"` |
| 正文无 H1 | 预览标题 = 文件名去扩展名，`title_source = "filename"` |
| 用户改标题 | 落盘文件的 H1 被改写；文件名用新标题 |
| 用户不改标题 | 正文与上传时逐字一致 |
| 同名已存在 | 生成 `名_YYYYMMDD_HHMMSS.md`，旧文件不受影响 |
| `.pdf` | 400，提示只支持 md/txt |
| 超过 2 MB | 400 |
| GBK 编码的 txt | 正常解码，预览不乱码 |

## 9. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| Agent 改错内容 | 笔记被改乱且无备份 | 唯一性约束 + 三级匹配；用户可自行在 NAS 上恢复（若开了快照） |
| 删除误操作 | 文件永久消失 | 二次确认列出完整路径；批量按钮需显式勾选；不提供「全选删除」快捷键 |
| 上传文件名冲突 | 覆盖已有笔记 | 硬编码规则：同名一律加时间戳 |
| 索引与文件不一致 | 搜到打不开 / 打不开还占位 | 写后立即同步 + 文件监控兜底 + 删除先删文件 |
| 大文件切片慢 | 上传卡顿 | 2 MB 上限；切片耗时记录在日志 |

**回滚**：三个接口与两个工具都是新增代码，回滚只需还原 `main.py` 的工具注册与 `routes.py` 的路由；数据库无结构变更，无需迁移。

## 10. 验收标准

1. 群里对 bot 说「把《X 笔记》里那段改成 Y」，它能调用 `angel_note_edit` 改成功，且索引页标题/行数同步更新；
2. 让它「整篇重写这篇笔记」，走的是 `angel_note_write`；
3. 让它删笔记，它明确回答「没有删除笔记的能力」；
4. WebUI 索引页：单条删除、批量删除都弹确认框，确认后文件与索引同时消失；
5. 点任意一行能看到正文，不再是 JSON；
6. 上传一个没有 H1 的 `.md`，弹窗标题默认是文件名；改标题后确认，落盘文件的 H1 是新标题，文件名也是新标题；
7. 上传同名文件两次，得到两个文件，旧的不被覆盖；
8. 手工在 NAS 上改一个已索引的 `.md`，下一轮扫描后索引页的行数与标题跟着更新。
